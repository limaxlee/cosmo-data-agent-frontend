# Migrating This Project Into a New GitHub Repo

A step-by-step guide to move the `cosmo-data-agent-frontend` codebase from this local
folder into a brand-new GitHub repository, plus how to install and run it afterwards.

**Assumed setup:** Windows 11, PowerShell terminal in VS Code, Node.js v24.x, npm 11.x, git installed.

---

## Part 1 — Create the empty GitHub repo

1. Go to <https://github.com/new>
2. **Repository name:** e.g. `cosmo-data-agent-frontend`
3. Visibility: Private (or Public).
4. **Important:** leave *Add a README*, *.gitignore*, and *license* all **unchecked** —
   you want a truly empty repo so your first commit is clean.
5. Click **Create repository** and copy the HTTPS URL shown, e.g.
   `https://github.com/<your-username>/cosmo-data-agent-frontend.git`

---

## Part 2 — Clone it locally

Open a **new** VS Code window, then open the Terminal (Ctrl + backtick) and run:

```powershell
cd "C:\Users\aleno\VSCode Projects"
git clone https://github.com/<your-username>/cosmo-data-agent-frontend.git cosmo-frontend-new
cd cosmo-frontend-new
```

`git clone` downloads the (empty) repo and creates the folder `cosmo-frontend-new`,
already wired up to GitHub. Git will warn *"you appear to have cloned an empty
repository"* — that is expected.

---

## Part 3 — What to copy

### Copy these — exactly as they are

| Item | What it is |
| --- | --- |
| `src/` (entire folder) | All your app code — pages, components, lib, providers, fonts, `globals.css` |
| `public/` (entire folder) | Static files served as-is (`suggested-questions.json`) |
| `package.json` | Dependency list + the `npm run ...` scripts |
| `package-lock.json` | Exact locked versions — copy it, do not regenerate |
| `tsconfig.json` | TypeScript config (includes the `@/*` path alias your imports rely on) |
| `next.config.mjs` | Next.js config |
| `postcss.config.mjs` | Tailwind v4 / PostCSS config |
| `eslint.config.mjs` | Lint rules |
| `components.json` | shadcn/ui config (needed if you ever add more UI components) |
| `.gitignore` | Tells git what never to commit |
| `.env.example` | Template of required env vars — safe to commit |
| `.env` | Your **real** local values. Copy the file, but see Part 4 |
| `README.md` | Project readme |
| `STRUCTURE.md` | Your architecture notes |

For reference, the full `src/` tree that must come across:


> The two `.woff2` font files are binary — copy them with File Explorer or `robocopy`,
> never by opening and pasting their contents.

### Do NOT copy these

| Item | Why |
| --- | --- |
| `node_modules/` | Hundreds of MB of downloaded libraries. `npm install` recreates it exactly from `package-lock.json` |
| `.next/` | Build output cache. Regenerated by `npm run dev` / `npm run build` |
| `.git/` | The **old** repo's history. Copying it would overwrite the new repo's connection to GitHub |
| `.husky/` | Only contains the auto-generated `_` folder; `npm install` recreates it (the `prepare` script runs `husky`) |
| `tsconfig.tsbuildinfo` | TypeScript incremental-build cache |
| `next-env.d.ts` | Auto-generated by Next.js on the first `npm run dev` |

### Doing the copy

**Option A — File Explorer (simplest).** Open the old folder, select everything *except*
`node_modules`, `.next`, `.git`, `.husky`, `tsconfig.tsbuildinfo`, and `next-env.d.ts`;
copy, then paste into `cosmo-frontend-new`. Turn on **View -> Hidden items** so you can
see `.env` and `.gitignore`.

**Option B — one PowerShell command** (run from anywhere):

```powershell
$src = "C:\Users\aleno\VSCode Projects\cosmo-data-agent-frontend"
$dst = "C:\Users\aleno\VSCode Projects\cosmo-frontend-new"
robocopy $src $dst /E /XD node_modules .next .git .husky /XF tsconfig.tsbuildinfo next-env.d.ts
```

`robocopy` copies recursively (`/E`), excluding those directories (`/XD`) and files
(`/XF`). An exit code of `1` means *"files copied successfully"* — it is not an error.

## Part 4 — Fix `.gitignore` before your first commit

The current `.gitignore` has the env lines **commented out**, so `.env` would get
committed to GitHub. Open `.gitignore` in the new folder, find this block near the middle:

```gitignore
# dotenv environment variable files
# .env
# .env.*
# !.env.example
```

and change it to:

```gitignore
# dotenv environment variable files
.env
.env.*
!.env.example
```

Now `.env` stays on your machine while `.env.example` (the safe template) is still
committed. The current `.env` only holds an app title, an input limit, and the backend
URL — no secrets — but this is the habit that keeps it that way.

## Part 5 — Install and run

Run all of these from inside `cosmo-frontend-new`.

### 1. Install dependencies

```powershell
npm install
```

Reads `package.json` + `package-lock.json` and downloads every library into a fresh
`node_modules/`. Takes 1–3 minutes the first time. It also runs the `prepare` script,
which recreates `.husky/`. You only rerun this when dependencies change.

### 2. Start the development server

```powershell
npm run dev
```

Starts Next.js in dev mode (with Turbopack) at **<http://localhost:3000>**. It
hot-reloads — save a file and the browser updates itself. Leave it running while you
work; press `Ctrl+C` in the terminal to stop it.

> Requires `.env` to exist with `NEXT_PUBLIC_API_BASE_URL` pointing at your backend,
> otherwise chat requests will fail. `NEXT_PUBLIC_*` variables are read at build/start
> time, so restart `npm run dev` after editing `.env`.

### 3. Check for code errors (optional)

```powershell
npm run lint
```

Runs ESLint over the codebase and prints style/correctness warnings. Changes nothing.

### 4. Build for production

```powershell
npm run build
```

Compiles and optimizes everything into the `.next/` folder. This is also the best full
type-check — if TypeScript is unhappy anywhere, the build fails and tells you where.
You do *not* need this for day-to-day development.

### 5. Run the production build

```powershell
npm start
```

Serves the compiled output from step 4 at <http://localhost:3000>. Must be run *after*
`npm run build` — it will not work on its own.

**Day to day you only ever need `npm install` once, then `npm run dev`.**

## Part 6 — First commit and push

```powershell
git add .
git status
```

`git status` lists what will be committed. **Check that `.env`, `node_modules/`, and
`.next/` are NOT in that list.** If `.env` shows up, redo Part 4, then run:

```powershell
git rm --cached .env
git add .
```

Then commit and push:

```powershell
git commit -m "Initial commit: cosmo data agent frontend"
git push -u origin main
```

`git push -u origin main` uploads your commit and sets `main` as the default branch to
push to from now on. If git says your branch is called `master`, run `git branch -M main`
first.

Refresh the GitHub page — your code is there. Once you have confirmed the new folder runs
correctly with `npm run dev`, you can delete the old folder.

## Quick reference

| Command | What it does |
| --- | --- |
| `git clone <url>` | Download a repo and link the local folder to GitHub |
| `npm install` | Download all dependencies into `node_modules/` |
| `npm run dev` | Run the app locally with hot reload (development) |
| `npm run lint` | Report code style / correctness issues |
| `npm run build` | Compile an optimized production build into `.next/` |
| `npm start` | Serve the production build (run after `npm run build`) |
| `git add .` | Stage all changes for the next commit |
| `git status` | Show what is staged / untracked — check before committing |
| `git commit -m "msg"` | Save the staged changes as a commit |
| `git push` | Upload commits to GitHub |
